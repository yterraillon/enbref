Scratch space pour les documents produits par des agents (Claude Code) : analyses de sécurité, plans/études en cours, brouillons de doc.

Non committé (voir .gitignore) : tout ce qui est ici est considéré jetable par défaut.
Si un document mérite de survivre (accepté, à jour, utile à l'équipe), promouvoir son contenu vers un emplacement canonique du repo (docs/, une issue GitHub, le code lui-même) au lieu de le laisser vivre indéfiniment ici. Pour les tâches et findings de fin de story, le skill /follow-up fait cette promotion : issue GitHub rattachée à la story pour ce qui est durable, checklist ## Suites dans la PR pour ce qui meurt au merge.
Ne jamais coller de secrets/valeurs réelles dans les fichiers de ce dossier (même s'il n'est pas committé, une valeur en clair reste un risque une fois exposée par un zip, un partage d'écran, etc.).
